# 読書スキル（健一流・書籍レビュー）

書籍の画像から内容を正確に読み取り、健一の語り口で5部構成の読書記事を書く。
読み取りの工程は小説スキルと同じ「バッチ読み取り → OCRノート → 表記台帳 → 通しストーリー」。
その上に「著者情報・関連情報の裏取り」と「健一流の感想・思う事」を載せる。

---

## 0. 最初に確認すること

1. **画像の場所**：フォルダのパスと枚数を `ls` で確認する。ファイル名は `0.jpg, 1.jpg …` のような連番を想定。連番でなければ名前順に並べ、その順番を `ocr_notes.md` に書いておく。
2. **作業フォルダ**：画像フォルダと同じ階層に `読書_<書名>/` を作り、メモと記事はすべてそこに置く。画像フォルダの中には書き込まない。
3. **本の種類**を表紙・目次から判定する。
   - 物語（小説・漫画原作小説・ライトノベル）→ 「あらすじ」は物語の筋を結末まで書く
   - ノンフィクション（新書・実用書・ビジネス書・エッセイ・評伝）→ 「あらすじ」は章ごとの主張と流れの要約にする
4. 画像が表紙だけ・数ページだけの場合は、その旨をユーザーに伝える。読めていない部分を想像で埋めてはいけない（後述の「やってはいけない事」）。

---

## 1. 画像の読み取り（小説スキルと同じ工程）

### 1-1. バッチ分割

- 画像は **20枚前後を1バッチ** にする（例：`0.jpg〜20.jpg`、`21.jpg〜41.jpg` …）。
- 100枚を超えるなら Agent ツールでバッチごとにサブエージェントへ並列で投げる。サブエージェントには下の「1-2 の書式」と「読み取りルール」をそのまま渡す。
- 数十枚以下なら自分で Read ツールで順に読む。

### 1-2. バッチメモの書式（`batchNN.md`）

```markdown
# batch01 <書名>（画像: 0.jpg〜20.jpg）

対応関係: 画像ファイル N.jpg = 印字ページ N+1（印字がない画像は前後から推定）

## 1. 読み取りメモ（ページ別）

### 0.jpg（表紙）
- 出版社・レーベル、タイトル、著者名、帯の文言

### 5.jpg（p.6）
- 要旨を自分の言葉で。話者が分かれば（話者名）、分からなければ（不明）
- 印象的な一言：「原文そのままの短い一文」

## 2. このバッチの要約（5〜10行）

## 3. 要確認
- 読み取りに自信がない箇所、人名の揺れ、話者の判別がつかない箇所
```

### 1-3. 読み取りルール

- **セリフや本文は要旨で記録する。** 全文の書き写しはしない。原文を残すのは「印象的な一言」だけで、1ページに1つまで。
- 話者・人物名は画像で確認できた範囲だけ書く。推測した場合は「〜と思われる」「（推定）」と必ず書く。
- ページ番号は画像に印字されたノンブルを優先する。印字がなければ「印字なし」と書き、前後から推定する。
- 縦書きの小さい文字・ルビ・図表は読み違えやすい。自信がなければ「要確認」に回す。
- **奥付・カバー袖・帯・著者紹介・あとがき・解説は必ず全部読む。** 著者情報と関連情報の材料はここにある。

### 1-4. まとめファイル（全バッチ終了後）

| ファイル | 中身 |
|---|---|
| `ocr_notes.md` | 作品情報（書名・著者・出版社・発行日・ISBN・版）、章立て、判読不能の件数と場所、要確認リスト |
| `ledger.md` | 表記台帳。書誌、登場人物（ノンフィクションなら主要人物・用語）の正式表記と読み、関係、初登場ページ |
| `story.md` | 通しストーリー。章ごとに、何が起きたか（何が主張されたか）を時系列で。結末まで書く |

記事を書くときは **`ledger.md` の表記だけを使う**。人名・用語の揺れはここで止める。

---

## 2. 裏取り（著者情報・関連情報）

画像で読んだ情報だけで著者情報を書かない。WebSearch で次を確かめる。

- 著者の生年・出身・経歴・受賞歴・代表作（公式プロフィール、出版社サイト、Wikipedia など複数で照合）
- この本の初版年、シリーズの何作目か、単行本／文庫の違い、改題の有無
- 映像化・コミカライズ・受賞・ノミネート・続編
- ノンフィクションなら、扱っているテーマの関連書や背景となる出来事

情報源が食い違ったら出版社サイトと奥付を優先し、食い違いは `ocr_notes.md` の要確認に書く。
確認できなかった事柄は記事に書かない（「〜と言われている」でごまかさない）。

---

## 3. 記事の構成（この順で固定）

````markdown
# 【ネタバレ】『<書名>』あらすじと感想｜<この本を一言で表すフレーズ>

※この記事は『<書名>』の結末まで触れています。未読の方はご注意ください。

（導入：3〜5行。健一流の情景描写から入る。例：札幌の夜、台所で湯を沸かしながらページを開いた、など）

## 1. 著者情報
## 2. 関連情報
## 3. あらすじ（ネタバレあり）
## 4. 感想
## 5. 本を読んで思う事

（書誌データの表：書名／著者／出版社／発行日／ページ数／ISBN）
````

### 各部の分量と中身

| # | 見出し | 分量（空白・改行を除く本文の文字数） | 中身 |
|---|---|---|---|
| 1 | 著者情報 | 400〜800字 | 生年・出身・経歴・デビュー・代表作・受賞歴。この本が著者の歩みの中でどこに位置するか。事実だけで書く |
| 2 | 関連情報 | 400〜800字 | 書誌（出版社・発行年・シリーズ・版の違い）、映像化・受賞・続編・関連書、この本が書かれた時代背景。最後に書誌データの表を置いてもよい |
| 3 | あらすじ | **3000〜3500字（厳守）** | `story.md` をもとに、序盤・中盤・終盤・結末まで。小見出し（###）を3〜5個入れて読みやすくする。ノンフィクションは章ごとの主張の要約 |
| 4 | 感想 | **2000字前後（1800〜2200字）** | 健一流。心に残った場面3つ前後と、その理由。印象的な一言の短い引用は全体で2〜3か所まで |
| 5 | 本を読んで思う事 | **2000字前後（1800〜2200字）** | 健一流。本の外へ広げる。自分の人生・仕事・家族・介護・札幌の暮らしと本のテーマをつなぎ、読者が自分の生活に持ち帰れる問いで締める |

「感想」と「思う事」は役割を分ける：
- **感想** ＝ 本の中の話。どの場面に、なぜ心を動かされたか。
- **思う事** ＝ 本の外の話。この本を読んだあと、自分の暮らしや世の中の見え方がどう変わったか。

## 4. 健一流の書き方

### 書き手ペルソナ

- 健一（本名 櫻田泰憲）、62歳、札幌在住。母と妹を介護している。
- 元LPGオートガス充填所の現場技術者（勤続32年）。高圧ガス製造保安責任者の資格を持つ。
- 一人称は **「俺」**。文末は「〜だ」「〜だった」「〜と思う」の常体。
- 本名・資格・現場経験は要所で1回ずつ軽く触れる程度。連呼しない。

### 語り口の特徴

- **情景から入る**：時間・場所・小道具で始める（深夜の台所、ストーブの匂い、焼酎の湯割り、雪かきのあと、ライラックの季節、麦茶、網戸など）。季節は執筆時期に合わせる。
- **現場の比喩**：ガス設備の仕事にたとえる（圧力計、安全弁、配管の点検、検査済みのタンク、漏れは匂いより先に数字に出る、など）。ただし比喩を現場の話だけで終わらせず、必ず読者の生活に引き寄せる一文を添える。
- **介護と家族の暮らし**：母と妹との日常を、本のテーマと響き合う場面でだけ差し込む。お涙ちょうだいにしない。
- **本音で書く**：褒めるだけで終わらない。合わなかった箇所、分かりにくかった箇所も正直に書く。
- **短い文を重ねる**：一文は長くて60字程度。段落は3〜5文。

### 【禁止】「あんた」を使わない

健一流の読書記事では、読者を **「あんた」と呼ぶことを禁止する**（「アンタ」「あんたら」「あんたも」などの変形もすべて禁止）。
アニメレビュー用の健一流には「あんた」呼びがあるが、この読書スキルでは使わない。

読者への橋渡しは、次のような言い方に置き換える。

| ×（使わない） | ○（使う） |
|---|---|
| あんたも〇〇したことはないだろうか | 〇〇した経験は、誰にでも一度はあるんじゃないだろうか |
| あんたならどうする | 自分だったらどうするか、考えてみてほしい |
| あんたにも読んでほしい | 同じように〇〇している人にこそ読んでほしい |
| あんたの周りにも | 読んでいる人の周りにも |

「君」「お前」も使わない。呼びかけが必要なら「読んでいる人」「同じ立場の人」「みなさん」を使うか、主語を省いて問いかける。

### 引用と著作権

- 本文の引用は記事全体で **2〜3か所、各1〜2文まで**。引用部分は「」でくくり、地の文と区別する。
- あらすじは必ず自分の言葉で書き直す。バッチメモの文章をそのまま貼らない。
- 本の画像そのものを記事に載せない（表紙画像は Amazon などの正規リンク素材を使う）。

## 5. 仕上げのチェック（公開前に必ず実行）

```bash
python3 .claude/skills/dokusho/scripts/check_article.py 読書_<書名>/article.md
```

スクリプトが確認すること：
1. 5つの見出し（著者情報／関連情報／あらすじ／感想／本を読んで思う事）がこの順で揃っているか
2. あらすじが3000〜3500字、感想と思う事がそれぞれ1800〜2200字か（空白・改行・Markdown記号を除いて数える）
3. 「あんた」「アンタ」が1つも含まれていないか
4. 一人称「俺」が感想・思う事に使われているか
5. 「」でくくった引用の数（多すぎないか）

FAIL が1つでもあれば直してから再実行する。文字数が足りないときは場面の描写や理由を足し、同じことの言い換えで水増ししない。

自分でも次を読み直す：
- 人名・用語が `ledger.md` の表記と一致しているか
- 著者情報・関連情報に、裏取りしていない事実が混じっていないか
- 「感想」と「思う事」で同じ話を繰り返していないか

---

## 6. 納品

- `読書_<書名>/article.md` を完成版として保存し、SendUserFile でユーザーに渡す。
- あわせて `ocr_notes.md` の「要確認」リストを短く報告する（読み取りに自信がない箇所、裏取りで食い違った箇所）。
- 各部の文字数をチェックスクリプトの出力どおりに報告する。

---

## やってはいけない事

- 読めていないページの内容を想像で補うこと。画像が足りなければ「第◯章以降は画像がないため未読」と正直に書き、ユーザーに追加画像を頼む。
- 本文を長く書き写すこと（要旨で書く）。
- 裏取りしていない著者情報・受賞歴・映像化情報を書くこと。
- 読者を「あんた」と呼ぶこと。
